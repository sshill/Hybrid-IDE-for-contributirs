## 1. Детальна еволюція архітектурних вимог

### 🏛️ v0.8.3: Фундамент 5-фазного регламенту та апаратний ценз
- **Виклик:** Безконтрольне спалювання токенів, сліпий обхід файлів (`ls`/`dir`), інлайн-виконання (`python -c`), загроза OOM на 16 ГБ RAM.
- **Вимоги:** 5 обов'язкових фаз, 5-рівнева матриця ШІ, ценз 16 ГБ RAM (заборона моделей $\ge 14\text{B}$).
- **Механізми:**
  - `pre_tool_hook.py`: Hard Deny `ls`/`dir` (код 1), Zero Inline-Eval (код 126).
  - LiteLLM Safe Budgeting: безпечний буфер -20% (6400 TPM, 800 RPM).
  - Валідатор структурної політики `validate_general_policy.py` (34 правила).

### 🏛️ v0.9.0 – v0.9.3: Модульність, SLA-маршрутизація та гігієна
- **Виклик:** Непрозорість очікування відповідей моделей, загроза випадкових відкатів Git, засмічення репозиторію тимчасовими звітами.
- **Вимоги:**
  1. Машиночитна централізація налаштувань (`policy_manifest.json`).
  2. Розрахунок часу інференсу (ETC) за квантом SLA 30 с.
  3. Двоконтурна політика Git (Dual Git Policy): автономні коміти вперед; деструктивні команди заблоковано.
  4. Repository Docs Hygiene Gate: заборонено звіти в корені; дозволено лише `implementation_plan.md` та `walkthrough.md`.
- **Механізми:** RouteLLM Throughput Dispatcher, `+!` Attention Gate, 5 віджетів взаємодії.

### 🏛️ v0.9.4 – v0.9.7: Бюджети, зациклення, декуплинг та Copilot CLI
- **Виклик:** Безкінечні цикли повторних помилкових дій, вичерпання лімітів при фіксованому бюджеті, розмивання системного промпту при перевищенні 20 КБ.
- **Вимоги:**
  1. Динамічний бюджет дій Фази 4 за обсягом плану (Dynamic Step Budget).
  2. Семантичний перехоплювач повторюваних дій на 2-му кроці (Semantic Loop Gate, W=4).
  3. Компакція конституційного ядра: жорсткий ліміт $\le 20,480$ байтів (v0.9.5).
  4. Декуплинг правил: поділ на глобальне ядро та локальний оверлей `AGENTS.md` (v0.9.6).
  5. Copilot Heavy-Only Gate: залучення Tier 4.5 суворо для складного рефакторингу та передрелізного E2E аудиту.
- **Механізми:** 4-Tier AI Battle Test, 2D-телеметрія ($S$, $N_{\text{in}}/N_{\text{out}}$), `diagnostic_runner.py --copilot-audit`.

### 🏛️ v0.9.8 – v0.9.10: Провененс, Brain-First ізоляція та форензік-захист
- **Виклик:** Втрата стану при перезавантаженні хоста (`/tmp`), колізії сесій, лазівки обходу перевірки коду (сесії `483326e2`, `7640bc31`).
- **Вимоги:**
  1. Brain-First персистентність: перенесення стану та логів у `<brain>/.system_generated/`.
  2. PreInvocation Hook: перехоплення `invocationNum == 1`, авто-ініціалізація нових чатів.
  3. Strict Hash Integrity: обов'язкова звірка SHA256 вихідного і зміненого файлу.
  4. In-Memory Replacement Simulation: симуляція заміни `old -> new` у пам'яті до дотику до диска.
  5. Shell State Isolation Gate: заборона шеллу перенаправляти вивід у системні файли ядра та леджер.
  6. Zero-CLI Exposure: видалення прапорця `--register` для усунення «відмивання хешів».
- **Механізми:** `locked_ledger()`, `pre_invocation_hook.py`, статичний кеш `tools_reference_v0.9.10.md`.

### 🏛️ v0.9.11: Довірений Анклав, Schema 1.2 HMAC Passports та Anti-Echo Gate
- **Виклик:** Колапс уваги в глибокій сесії `ea70f7eb...` (2813 кроків, >1.2M токенів), несанкціоноване вторгнення в ядро.
- **Вимоги:**
  1. Повна ізоляція генерації в Довірений Анклав (Trusted Sidecar Enclave на `127.0.0.1:8765`).
  2. Zero-SHA Separation: оркестратор Antigravity не пише код на диск і не випускає паспорти.
  3. Криптографічні HMAC-SHA256 паспорти Schema 1.2 (`MINTED -> RESERVED -> APPLIED / FAILED`).
  4. Anti-Fake Ledger Gate: Master HMAC Secret (`.core_master_hmac.secret` mode 0600).
  5. Anti-Echo Gate: відхилення промпт-ехо за шинґлами $> 0.25$.
- **Механізми:** `core/enclave/enclave_daemon.py`, fail-closed AST gate, атомарний `fsync()`.

### 🏛️ v0.9.12: Git State Seal Gate, Форензік-Аудитор чату та Zero-Omission
- **Виклик:** Ризик незапечатаного стану Git перед walkthrough; декларативні віджети без розрахунку.
- **Вимоги:**
  1. Phase 5.2 Git State Seal Gate: обов'язковий автономний `git commit` перед публікацією `walkthrough.md`.
  2. Unified Chat Context Auditor (`core/verify/chat_context_auditor.py` з 12 unit-тестами).
  3. Step Budget Diagnostic Immunity: read-only команди не витрачають квоту дій.
  4. Mandatory Proactive Telemetry Gate (Zero-Omission): виміряний віджет 2D-телеметрії у блоці коду `text` у Фазах 1, 3, 5.
  5. Багатопотокова надійність Анклаву (`ThreadPoolExecutor`).
- **Тестове покриття:** 45 unit-тестів провененсу + 12 unit-тестів аудитора + 37/37 перевірок політики.
