# Архітектура семантичного кешування, детермінованого RAG та Compiled AI Guardrails

**Версія ядра:** Hybrid IDE Kernel v0.9.12  
**Категорія:** Дослідження та архітектурне проектування (Tier 3 Knowledge Base)  
**Цільова платформа:** Debian Linux, Python 3.10–3.13 (Суворо Stdlib Zero-Dep), ліміт 16 ГБ RAM.  
**Ключові цілі:** Утримання контексту на регламенті (усунення Attention Drift) та скорочення сторонніх токенів ($N_{\text{in}}$).

---

## 1. Контекст та постановка інженерної проблеми

Під час довготривалих сесій (800+ кроків) автономні агенти стикаються з двома деградаціями:
1. **Ерозія уваги та амнезія після компакцій (Attention Drift & Compaction Amnesia):**  
   Коли розмір транскрипту перевищує 40k–80k токенів або вмикається `<CONTEXT_SUMMARY>`, генеративні моделі втрачають зв'язки з регламентом. Агенти починають викликати застарілі шляхи або замовкати (як зафіксовано у сесії `f38b8ff7`).
2. **Марнотратство сторонніх токенів (Cloud Token Depletion):**  
   Зчитування повних модулів ядра (наприклад, `phase4_provenance.py` має 893 рядки $\approx$ 9 000 токенів $N_{\text{in}}$) для аналізу однієї функції випалює квоти хмарних провайдерів (Groq, Claude Sonnet), хоча 95% переданого коду є надлишковим шумом.

## 2. Три стовпи оптимізації архітектури

### 2.1. Семантичне кешування (Дворівневий каскад L1/L2)

#### Проблема класичного векторного RAG:
Підключення важких векторних баз (Redis, Qdrant) порушує принцип **Zero-Dependency stdlib-only**. Крім того, тримання в локальній Ollama одночасно генеративної моделі (`qwen2.5-coder:1.5b`) та моделі ембеддінгів (`nomic-embed-text`) на машині з 16 ГБ RAM призводить до *Swap Lag* (2–4 секунди на вивантаження та завантаження ваг у VRAM/пам'ять).

#### Архітектурне рішення Hybrid-IDE:
1. **L1: Exact & 8-Token Shingle Hash Cache (Безнейронний шар):**
   - Розрахунок `hashlib.sha256` від нормалізованого тексту запиту.
   - Порівняння 8-токенних шинглів (вже наявне в `diagnostic_runner.py`).
   - Покриває до 80% типових повторюваних операцій (виклики `/reglament`, `/bridge`, аудити, шаблони звітів).
   - Час реакції: `< 0.0001 с`, споживання RAM: `0 МБ`, витрати токенів: `0`.
2. **L2: Stdlib Cosine / BM25 Cache (Легкий векторний шар):**
   - Збереження векторних представлень статей бази знань у статичному JSON-індексі: `docs/knowledge/.cache/embeddings.json`.
   - Обчислення косинусної схожості без сторонніх бібліотек за допомогою стандартного `math`:
     $$\text{Cosine}(A, B) = \frac{\sum_{i=1}^n A_i B_i}{\sqrt{\sum_{i=1}^n A_i^2} \sqrt{\sum_{i=1}^n B_i^2}}$$
   - Якщо $\text{Cosine}(A, B) \ge 0.88$, система миттєво повертає готовий фрагмент бази знань без виклику нейромереж.

### 2.2. Детермінований RAG (Exact Match & Target Retrieval)

**Найвищий пріоритет для зменшення $N_{\text{in}}$ на 90–95%:**
- **Суть:** Якщо промпт містить точний якір (FormID, SHA256-хеш, назву класу чи сигнатуру), система блокує сліпий генеративний пошук.
- **Робота через Git та AST:**
  1. Інспектор `phase1_inspect.py` парсить AST файлу (`ast.parse`) без виконання коду.
  2. Вилучається виключно цільовий вузол (`FunctionDef` / `ClassDef`).
  3. У контекст подається мікро-фрагмент на 30–50 рядків (~300 токенів замість 9000).
- **Результат:** Сесія залишається у Зеленій зоні (🟢 Зона 1, $\le 3000$ tok) сотні кроків поспіль.

### 2.3. Compiled AI Guardrails (Instructor на Pure Stdlib)

**Суть:** Переведення регламентних правил із текстового промпту на детерміністичні компіляційні фільтри.

1. **Schema Enforcement без Pydantic:**
   - Модулі `re` та `json`.
   - Розширення `phase2_router.py` на всі фази регламенту (`validate_phase1_banner`, `validate_phase3_report`, `validate_phase5_walkthrough`).
2. **Self-Correction Retry Loop в Анклаві:**
   - Анклав (`enclave_daemon.py`) валідує вивід LLM на відповідність схемі до його виводу в чат.
   - При порушенні схеми або "мовчанні" Анклав локально (0 хмарних токенів) повертає диференційний промпт виправлення (до 2 спроб).
   - Чат отримує виключно валідні кроки.

## 3. Матриця розміщення компонентів у дереві `core/`

| Компонент | Цільовий файл | Роль та обов'язки |
|---|---|---|
| **Семантичний кеш (L1/L2)** | `core/router/semantic_cache.py` | Shingle L1 + Stdlib Cosine/BM25 L2 кешування відповідей та знань. |
| **Детермінований RAG** | `core/inspect/phase1_inspect.py` | Прапорець `--extract-symbol` для вилучення мікро-фрагментів AST. |
| **Output Schema Guardrails** | `core/router/phase2_router.py` | Валідація форматів звітів усіх 5 фаз через чисті регулярні вирази. |
| **Первинний контроль Анклаву** | `core/enclave/enclave_daemon.py` | Перевірка кешу перед викликом LLM та Self-Correction retry-цикл. |
| **Hard Deny Gate** | `core/hooks/pre_tool_hook.py` | Блокування сліпого RAG-пошуку при наявності точного якорного символу. |

## 4. Очікуваний ефект від впровадження

1. **Збереження фокусу на регламенті:** 0 випадків "мовчання" моделі або галюцинацій щодо команд (запобігання інцидентам на зразок сесії `f38b8ff7`).
2. **Економія токенів:** Скорочення витрат вхідного контексту $N_{\text{in}}$ для завдань модифікації та аналізу коду на **85–95%**.
3. **Апаратна безпека:** Робота в межах 16 ГБ RAM без потреби запускати важкі векторні СУБД чи сторонні моделі ембеддінгів із затримками свапу.
4. **Суверенність:** Повна відповідність ліцензійним та безпековим принципам Zero-Dependency stdlib Python.
